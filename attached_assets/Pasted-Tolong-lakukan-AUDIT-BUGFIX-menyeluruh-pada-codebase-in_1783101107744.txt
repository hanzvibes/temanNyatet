Tolong lakukan AUDIT & BUGFIX menyeluruh pada codebase ini dengan aturan ketat berikut:

## SCOPE & BATASAN (WAJIB DIPATUHI)
- JANGAN mengubah, menghapus, atau menyederhanakan fitur/behavior yang sudah ada
- JANGAN mengubah struktur routing, nama komponen, atau public API kecuali itu sendiri penyebab bug
- JANGAN refactor besar-besaran "karena lebih rapi" — fokus HANYA ke bug & error
- Kalau nemu potential improvement di luar scope bug, catat di laporan, JANGAN langsung dieksekusi
- Setiap perubahan harus minimal dan targeted (surgical fix, bukan rewrite)

## YANG PERLU DIPERIKSA
1. Runtime errors & console warnings (browser + server log)
2. TypeScript/JS errors, type mismatch, unhandled null/undefined
3. Broken imports, unused variables, dead code yang bikin build gagal
4. Environment variable yang belum di-set / hardcoded secret
5. API routes yang error handling-nya lemah (unhandled promise rejection, missing try-catch)
6. Build errors kalau dijalankan `next build` (karena target deploy ke Vercel)
7. Masalah kompatibilitas Next.js dengan Vercel (misal: penggunaan Node API yang gak support di edge runtime, dynamic import yang salah, file system access yang gak jalan di serverless)
8. Missing dependencies di package.json vs yang dipakai di kode
9. Konfigurasi next.config.js / vercel.json yang berpotensi bikin deploy gagal

## OUTPUT YANG DIMINTA
1. Jalankan `next build` (atau build command yang sesuai) dan pastikan LOLOS tanpa error sebelum lapor selesai
2. List semua bug yang ditemukan (before/after, file & line)
3. List semua fix yang dilakukan beserta alasannya
4. List "potential issue" yang TIDAK diperbaiki karena di luar scope (biar aku yang putuskan)
5. Konfirmasi bahwa fitur utama masih berjalan sama seperti sebelumnya (jelaskan cara kamu verifikasi ini)

## KHUSUS DEPLOY VERCEL
- Pastikan gak ada env var yang required tapi belum masuk ke .env.example
- Pastikan gak ada absolute local path atau dependency yang cuma jalan di local (misal fs.readFileSync ke folder yang gak ke-deploy)
- Cek apakah ada penggunaan `"use client"` yang salah taruh atau server component yang manggil browser API
- Kalau ada API call ke localhost, tandai sebagai warning

Setelah selesai, kasih ringkasan singkat: "AMAN UNTUK DEPLOY" atau "MASIH ADA RISIKO: [sebutkan]"
